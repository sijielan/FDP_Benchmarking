# Running the MySQL (TPC-C) experiments

Scripts, workloads and config for the MySQL experiments: file-system sensitivity and discard sensitivity.

```
how_to_run/
├── workloads/   tpcc-mysql binaries and table schema
├── script/      main experiment script + monitors
└── config/      my.cnf and RUH (write-hint) policy notes
```

## Setup

All runs use Percona Server + tpcc-mysql on one NVMe SSD. The TPC-C parameters are set at the top of
`combined_test.sh` and can be changed per experiment:

| Variable | Meaning | Default |
|---|---|---|
| `WAREHOUSE` | Number of warehouses | `6000` |
| `TPCCHOUR` | Run length (hours) | `10` |
| `WARMUP` | Warmup (seconds) | `300` |
| `CONNECTIONS` | Client connections | `128` |

The buffer pool is 64 GB (`innodb_buffer_pool_size` in the generated `my.cnf`).

Three file-system configurations, each run in `cns` (Conv.) and `fdp` mode (6 runs total):

| Configuration | `FS_TYPE` | `DISCARD` |
|---|---|---|
| ext4 + discard | `ext4` | `1` |
| ext4 + nodiscard | `ext4` | `0` |
| xfs + nodiscard | `xfs` | `0` |

## Requirements

- Linux, root, an FDP-capable NVMe SSD, `nvme-cli` with `fdp` support, `sysstat`.
- The patched Percona Server installed in `/usr/local/mysql` (see [`../compile`](../compile)).
- `script/getRUHWrite.sh`: `MAX_RUAMW=4349952` is device-specific; set it from `nvme fdp status` on your SSD.

## Layout

The script expects the tpcc-mysql directory layout (its parent directory is the tpcc-mysql root):

```
tpcc-mysql/
├── load.sh  create_table.sql  tpcc_load  tpcc_start      <- workloads/
└── run_scripts/
    ├── combined_test.sh  waf_monitor.sh  disk_monitor.sh  measure_dev   <- script/
    └── rocksdb/getRUHWrite.sh                                           <- script/
```

## Run

> **Warning:** the script formats the device, recreates the namespace, and mounts it at `/mnt/test`.
> Only run it on a dedicated test drive.

Set the file system and discard at the top of `combined_test.sh` (lines 30–31):

```bash
FS_TYPE="ext4"   # ext4 | xfs
DISCARD=1        # 1 = discard on, 0 = off
```

Then run it, passing the NVMe controller number and the mode:

```bash
sudo ./combined_test.sh <nvme_ctrl_num> <fdp|cns>
# e.g. /dev/nvme2 in FDP mode
sudo ./combined_test.sh 2 fdp
```

The script recreates the namespace, runs mkfs and mounts, initializes MySQL, loads TPC-C, runs it for `TPCCHOUR` hours,
and samples WAF every 10 minutes. `/etc/my.cnf` is generated by the script; `config/my.cnf` is a copy for reference.

Results go to `tpcc-mysql/results/<timestamp>_nvme<N>_<mode>_mysql_only_tpccW<WAREHOUSE>_<TPCCHOUR>hr/`.
The WAF over time is in `<mode>_waf_monitor.csv` (`WAF_INTERVAL` column).
